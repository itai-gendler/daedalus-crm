# Hosted writes require the selected workspace entitlement where their actual call path checks it

This additional conjunctive Rule selects the listed web CRM entity mutations, including hosted AI Config changes through Setting writes. It evaluates each actual data-plane call and access path using that call's exact selected Workspace configuration. Another owner's workspace, an arbitrary membership or any paid workspace cannot supply it. Caller-authority Rules remain separate. Hosted MCP mutation remains unavailable.

In multi-tenant mode `clientForCall` first uses an explicitly established `currentTenant()` context, otherwise resolves the request's `crm_session`. Missing or unresolvable context throws without default-database fallback. Uncached resolution verifies the session and implemented cutoff, then resolves the exact account/workspace membership selected by the subject and workspace claim. Missing membership yields no tenant. That workspace determines the database file and computed writability.

At resolution time, compute entitlement in this order: SUSPENDED is false; otherwise a non-null Paid expiry strictly later than now is true, including TRIAL; otherwise ACTIVE is false; otherwise Trial expiry strictly later than now determines the result. Equality is expired. TRIAL does not exclusively use Trial expiry, and ACTIVE without future Paid expiry does not fall back to a future Trial expiry.

Token resolution caches its context, including writability or null, for less than ten seconds. A cache hit rereads neither membership nor entitlement and does not recompare expiry to the clock. Explicit tenant contexts reuse supplied writability without an independent ten-second refresh. The Rule preserves these freshness boundaries rather than enforcing immediate suspension/expiry on every mutation. `requireUser()` separately verifies identity, immediately checks hosted session cutoff and finds the actual active mapped CRM account; cached tenant resolution does not promise immediate membership refresh.

The hosted Prisma proxy checks `ctx.writable` on model create, createMany, createManyAndReturn, update, updateMany, updateManyAndReturn, upsert, delete and deleteMany calls, and top-level $executeRaw/$executeRawUnsafe. False throws TrialExpiredError before that guarded call. Reads need no writability but retain identity, membership and record-scope Rules.

Opening $transaction selects the tenant with write false and supplies the real client to its callback. Writes through tx bypass the outer proxy's expiry gate. $queryRaw/$queryRawUnsafe likewise receive no write classification; an eventual SQL mutation does not create one. For actual unguarded callback/client dispatch, this additional entitlement gate is neutral: it grants no caller authority or independent mutation permission, and the operation's identity, authority and explicit callback checks still govern. Control-database and direct workspace-client calls retain their own checks. Selfhost/native paths outside multi-tenant mode have no hosted expiry gate; runtime mode is not a customer Writable fact.

Manual pool release and undo-release use guarded outer writes. Claim/undo-claim and ownership-carried work use callback writes; preliminary legacy-signing-owner backfill can encounter a separate guarded write first. Customer/signing check-then-write and Lead conversion/merge use callback transactions with their actual identity/matching/concurrency checks. An existing conversation turn uses a callback, while creating a new conversation first is a separate outer guarded write. Mixed operations retain order: callback changes can commit before a later guarded call fails, and a caught audit failure cannot establish rollback. No uniform expiry blockade or universal atomic rollback is promised.

The unattended alternative applies the identical selected-workspace and actual-call-path entitlement decision to the page-triggered automatic pool scan. It adds no unattended claim, undo or other independent authority; the book-bound automatic-scan Rule remains conjunctive.
